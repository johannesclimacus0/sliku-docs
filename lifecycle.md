# Жизненный цикл запроса

## Точка входа

Путь HTTP-запроса начинается с `public/index.php`.
Скрипт подключает `vendor/autoload.php`, создает приложение через `App\Bootstrap\AppFactory::create()` и вызывает `run()`.
Composer находит классы по namespace, а Slim собирает из HTTP-данных PSR-7 request и отправляет клиенту полученный response.

`AppFactory` загружает `.env`, получает контейнер из `config/container.php` и создает Slim через PHP-DI Bridge.
Затем он подключает middleware, обработчик ошибок, стратегию вызова контроллеров и `routes/api.php`.
В `create()` можно передать готовый `DI\Container`, например, чтобы проверить приложение с другим набором зависимостей.

## Слой middleware

Middleware работает вокруг следующего обработчика: проверяет запрос, добавляет атрибут или меняет ответ.
**В Slim последний добавленный слой выполняется первым на входе.**

Внешние слои регистрируют запрос, применяют CORS и измеряют время ответа.
Внутри находятся обработчик ошибок, маршрутизация, разбор тела и проверка JSON.
При доступном Clockwork дополнительно подключается профилирование.
Маршрутные middleware, например `JwtAuthMiddleware` и `RequireVerifiedEmailMiddleware`, защищают выбранные группы маршрутов.

## Разбор и выбор обработчика

Для JSON-запросов используется `JsonBodyParser`. Он преобразует JSON-объект в `stdClass` и отклоняет некорректный JSON, а также JSON-массивы и простые значения вместо объекта.
`RequireJsonBodyMiddleware` требует объект для POST, PUT и PATCH.
Отдельное исключение есть для загрузки аватара: маршрут `auth.avatar.upload` принимает multipart.

Когда маршрут найден, `RouteEntityBindingStrategy` готовит аргументы для обработчика.
Он передает request и response, аргументы маршрута и атрибуты запроса, а при подходящей типизированной сущности загружает ее через Doctrine.
Контейнер завершает вызов контроллера и разрешает его зависимости.

Для `GET /users/1` параметр `{user}` становится аргументом `User $user`.
Если записи нет, клиент получит 404 еще до вызова метода.
Проверка права просмотра остается задачей контроллера или сервиса приложения.

## Ответ и исключение

Контроллер возвращает `ResponseInterface`.
`App\Http\JsonResponse` создает JSON-тело и устанавливает статус и Content-Type.
Ответ проходит обратно через middleware, которые могут добавить заголовки или записать итоговые данные в журнал.

Если возникает исключение, `JsonErrorHandler` переводит его в единый JSON-формат.
Известная ошибка проверки данных получает 422, неожиданная - 500 с общим сообщением; подробности серверной ошибки уходят в журнал.
