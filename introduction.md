# Знакомство со Sliku

## Для чего нужен стартер

Здесь уже есть готовая основа приложения, на базе которой можно разрабатывать и подключать собственные модули, постепенно расширяя его функциональность.
В нем уже собраны JSON API, обработка ошибок, валидация, JWT-аутентификация, очереди, события, почта и файловое хранилище.

В основе проекта лежат [Slim](https://www.slimframework.com/) и Doctrine.

## Первый запуск

В статье [Установка](/docs/{{version}}/installation) пошагово описаны настройка окружения, подготовка файла .env, запуск API и пользовательского интерфейса, выполнение миграций и запуск обработчика фоновых задач.

Для понимания организации проекта и его основных компонентов можно ознакомиться с разделом [Структура проекта](/docs/{{version}}/structure).

Компоненты приложения, база данных и пользовательский интерфейс работают независимо друг от друга. 
При возникновении ошибок важно определить, на каком этапе нарушается работа приложения. 
Основные способы выявления и устранения проблем описаны в разделе [Диагностика](/docs/{{version}}/troubleshooting).

## Изучение исходного кода

Удобный первый сценарий - запрос к `/health/live`.
От него можно пройти по маршруту в `routes/api.php`, контроллеру и ответу.

Можно знакомиться с проектом в таком порядке:

1. [Жизненный цикл запроса](/docs/{{version}}/lifecycle).
2. [Конфигурация](/docs/{{version}}/configuration) и [контейнер](/docs/{{version}}/container).
3. [Маршруты](/docs/{{version}}/routing), [контроллеры](/docs/{{version}}/controllers), [валидация](/docs/{{version}}/validation).
4. [База данных](/docs/{{version}}/database), [аутентификация](/docs/{{version}}/authentication) и [права доступа](/docs/{{version}}/authorization).
5. [События](/docs/{{version}}/events), [очереди](/docs/{{version}}/queues) и остальные сервисы по мере необходимости.

## Дальнейшая разработка

При разработке рекомендуется придерживаться принципа разделения ответственности: контроллер принимает HTTP-запрос, DTO обеспечивает передачу данных между компонентами, сервис реализует бизнес-логику, репозиторий отвечает за доступ к данным, а контроллер формирует и возвращает HTTP-ответ.

Примеры генерации заготовок и явной регистрации находятся в статье [Консоль](/docs/{{version}}/console).
