# HTTP-клиент

Для запросов к внешним API в стартере используется Symfony HttpClient. 
Он позволяет отправлять HTTP-запросы, передавать данные и обрабатывать ответы сторонних сервисов.

Клиент доступен через `Symfony\Contracts\HttpClient\HttpClientInterface` и внедряется в классы приложения через DI-контейнер.

## Подключение клиента

Настройки клиента находятся в `config/settings/http_client.php`, а его определение для контейнера - в `config/definitions/http_client.php`.

Например, так можно получить данные из внешнего API:

```php
use Symfony\Contracts\HttpClient\HttpClientInterface;

final class RemoteStatus
{
    public function __construct(
        private HttpClientInterface $http,
    ) {}

    public function read(): array
    {
        $response = $this->http->request('GET', 'https://example.test/status');

        return $response->toArray();
    }
}
```

Метод `toArray()` преобразует JSON-ответ в массив PHP. Если сервер вернёт ошибочный HTTP-статус, некорректный JSON или произойдёт сбой сети, потребуется обработать соответствующее исключение.

Передача клиента через конструктор также упрощает тестирование: вместо реального HTTP-клиента можно подставить `MockHttpClient`.

## Параметры запросов и ответы

Symfony HttpClient позволяет передавать параметры и данные через опции запроса:

- `query` - параметры URL;
- `json` - данные, которые будут отправлены в формате JSON;
- `headers` - HTTP-заголовки.

Например, отправка данных во внешний сервис:

```php
$response = $http->request('POST', 'https://example.test/reports', [
    'headers' => ['Accept' => 'application/json'],
    'json' => [
        'user_id' => 42,
        'format' => 'csv',
    ],
]);

$status = $response->getStatusCode();
$body = $response->getContent(false);
```

`getStatusCode()` возвращает HTTP-статус. Метод `getContent(false)` позволяет прочитать тело ответа даже при статусах 4xx или 5xx, не выбрасывая исключение только из-за статуса.

Успешное получение ответа ещё не означает, что операция выполнена правильно.
При интеграции с внешними сервисами нужно учитывать HTTP-статус и проверять ожидаемую структуру данных.

## Тайм-ауты и обработка ошибок

В стартере заданы общие ограничения для запросов:

| Параметр        | Значение по умолчанию | Назначение                               |
|-----------------|-----------------------|------------------------------------------|
| `timeout`       | 10 секунд             | Максимальное ожидание сетевой активности |
| `max_duration`  | 30 секунд             | Максимальная общая длительность запроса  |
| `max_redirects` | 5                     | Максимальное число перенаправлений       |

Для отдельных интеграций эти параметры можно переопределять при необходимости.

Symfony HttpClient работает с ответами частично отложенно.
Поэтому ошибка может возникнуть не в момент вызова `request()`, а позже, при получении статуса или чтении тела ответа. 
Обработку исключений стоит предусматривать для всей операции.

## Фоновые запросы

Если запрос к внешнему API занимает много времени и его результат не нужен пользователю сразу, такую операцию можно перенести в [очередь](/docs/{{version}}/queues).

При этом задания могут выполняться повторно после сбоя.
Например, внешний сервис мог принять POST-запрос, но ответ не дошёл до приложения. 
Повторная попытка в таком случае способна создать дублирующую операцию. 
Для подобных сценариев стоит предусмотреть механизм идемпотентности, если внешний API его поддерживает.

Для доставки событий во внешние системы в стартере также предусмотрены [вебхуки](/docs/{{version}}/webhooks). 
Они подходят для сценариев, в которых приложению необходимо сообщать другим сервисам о произошедших событиях.
