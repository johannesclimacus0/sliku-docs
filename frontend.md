# Фронтенд

## Запуск и сборка

Для локального запуска из корня проекта установите зависимости и запустите Vite:

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

Интерфейс будет доступен по адресу http://localhost:5173.

Фронтенд можно также запустить через Docker Compose:

```bash
./run --profile frontend run --rm --no-deps frontend npm ci
./run --profile frontend up -d frontend
```

Для проверки качества кода и production-сборки предусмотрены отдельные команды:

```bash
npm --prefix frontend run check:lint
npm --prefix frontend run build
```

`check:lint` запускает ESLint и проверку Prettier, а `build` выполняет проверку TypeScript через `vue-tsc --build` и сборку Vite. 
Для автоматических исправлений доступны `lint:fix` и `format`: первая команда исправляет поддерживаемые правила ESLint, вторая форматирует файлы.

## Организация приложения

Точка входа `frontend/src/main.ts` создаёт Vue-приложение, подключает Pinia, маршрутизатор и общие стили. Для импортов из `frontend/src/` настроен псевдоним `@`.

Основной код интерфейса распределён по каталогам:

| Каталог        | Назначение                              |
|----------------|-----------------------------------------|
| `views/`       | Страницы приложения                     |
| `components/`  | Переиспользуемые компоненты             |
| `layouts/`     | Общие макеты страниц                    |
| `router/`      | Маршруты и правила переходов            |
| `stores/`      | Состояние приложения в Pinia            |
| `services/`    | Запросы к API и клиентские сервисы      |
| `composables/` | Переиспользуемая логика Composition API |

Например, состояние авторизации находится в `stores/auth.ts`, HTTP-клиент - в `services/http.ts`, а операции входа и регистрации - в `services/auth.ts`.

Vue Router работает в history mode и загружает страницы по мере перехода к ним. 
Метаданные маршрутов `requiresAuth`, `admin` и `guest` позволяют ограничивать навигацию: неавторизованный пользователь перенаправляется на страницу входа, а обычный пользователь не попадает на административные экраны.

Перед первым переходом приложение пытается восстановить сессию. 
При этом ограничения на фронтенде отвечают только за навигацию. 

## HTTP-запросы и сессия

Для работы с API используется настроенный экземпляр Axios. 
По умолчанию запросы отправляются с префиксом `/api`; другой адрес можно указать через `VITE_API_BASE_URL`.

Клиент отправляет cookie с помощью `withCredentials`, использует тайм-аут 15 секунд и заголовок `Accept: application/json`. 
Обёртка `request<T>()` извлекает поле `data` из успешного ответа, а ошибки преобразует в `ApiRequestError` с HTTP-статусом и идентификатором запроса.

Пример обращения к защищённому endpoint:

```ts
import { request } from '@/services/http'
import { useAuthStore } from '@/stores/auth'

const auth = useAuthStore()

const overview = await auth.withToken((token) =>
  request({
    url: '/account/overview',
    headers: { Authorization: `Bearer ${token}` },
  }),
)
```

Access-токен хранится в памяти Pinia и не сохраняется в браузерное хранилище. 
После перезагрузки страницы метод `restore()` обращается к endpoint обновления токена и загружает данные текущего пользователя.

Если защищённый запрос возвращает 401, `withToken()` пытается обновить access-токен и повторяет запрос один раз. 
Одновременные попытки обновления внутри одного store используют общий Promise, чтобы не отправлять несколько одинаковых запросов.
