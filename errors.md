# Обработка ошибок

## Единый формат ответа

`App\Handlers\JsonErrorHandler` подключается в `AppFactory` как обработчик ошибок Slim.
Он собирает JSON-ответ из исключения с помощью `App\Http\JsonResponse`.
Вместо PHP stack trace клиент видит код ошибки и понятное сообщение.

```json
{
  "error": {
    "code": "ENTITY_NOT_FOUND",
    "message": "Ресурс не найден"
  }
}
```

По HTTP-статусу можно понять тип ошибки, а по `error.code` - ее конкретную причину.

## Исключения и HTTP-статусы

Обработчик распознаёт исключения, реализующие `App\Exceptions\ApiErrorException`, и сопоставляет их с HTTP-статусами.

| Исключение              | Статус | Значение                              |
|-------------------------|--------|---------------------------------------|
| `UnauthorizedException` | 401    | Требуется аутентификация              |
| `ForbiddenException`    | 403    | Доступ запрещён                       |
| `InvalidInputException` | 400    | Некорректные входные данные           |
| `ValidationException`   | 422    | Данные не прошли валидацию            |
| `NotFoundException`     | 404    | Ресурс не найден                      |
| `ConflictException`     | 409    | Конфликт с текущим состоянием ресурса |

`ValidationException` наследуется от `InvalidInputException`, но получает отдельный статус `422`. Для ошибок валидации в ответ также добавляется `error.details` с сообщениями по полям. У других ошибок этого поля обычно нет.

Когда привязка сущности маршрута не находит запись через Doctrine, возникает `EntityNotFoundException`, который преобразуется в ответ `404`.

## Собственные ошибки приложения

Для конкретных ситуаций можно создавать собственные исключения. 
Базовые `ConflictException`, `InvalidInputException` и `NotFoundException` абстрактны, поэтому от них наследуются классы с более точным смыслом.

Например, если профиль временно нельзя изменять:

```php
namespace App\Modules\Account\Exceptions;

use App\Exceptions\ConflictException;

final class ProfileLockedException extends ConflictException
{
    public function __construct()
    {
        parent::__construct('Профиль временно недоступен для изменения');
    }

    public function errorCode(): string
    {
        return 'PROFILE_LOCKED';
    }
}
```

Достаточно выбросить `ProfileLockedException` в нужном месте приложения. 
Общий обработчик сформирует ответ со статусом `409` и кодом `PROFILE_LOCKED`.
Сообщения известных ошибок со статусами ниже `500` могут попадать в ответ API, поэтому они должны быть понятными и не раскрывать секреты или внутренние детали системы.

## Ошибки маршрутизации и сбои сервера

Исключения `Slim\Exception\HttpException` сохраняют свой HTTP-статус. 
Для них формируются коды вида `HTTP_404` и `HTTP_405`. 
При ответе `405 Method Not Allowed` также передаётся заголовок `Allow` со списком поддерживаемых методов.

Неожиданные исключения преобразуются в ответ `500` с кодом `INTERNAL_SERVER_ERROR` и общим сообщением «Внутренняя ошибка сервера». 
Подробности не отправляются клиенту, но серверные ошибки от `500` записываются через `LoggerInterface` вместе с исключением.

`AppFactory` включает логирование ошибок Slim, не открывая их подробности в HTTP-ответе. 
Поэтому даже при `APP_DEBUG=true` клиент не получает stack trace. 
Настройки логирования находятся в `config/settings/logging.php` и `config/definitions/logger.php`.

## Поиск причины ошибки

- **400** - проверить `Content-Type`, формат JSON и состав запроса.
- **401** - проверить аутентификацию и состояние сессии.
- **403** - проверить права доступа и необходимость подтверждения email.
- **404** - проверить адрес маршрута и наличие запрашиваемого ресурса.
- **422** - прочитать `error.details` и проверить значения конкретных полей.
- **500** - посмотреть серверные логи, подключения к базе данных и доступность внешних сервисов.
