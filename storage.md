# Файловое хранилище

Через `App\Storage\Storage` можно читать и записывать файлы, используя Flysystem.
В стартере есть два локальных диска: `public` для доступных клиенту файлов и `private` для внутренних данных.
Сервис выбирает диск по имени и передает относительный путь.

Диск выбирается по имени, а пути к файлам задаются относительно его корневого каталога.

Реализация находится в `app/Storage/Storage.php`, `Disk.php` и `DiskFactory.php`.

## Настройка дисков

В `config/settings/storage.php` диск по умолчанию выбирается через `STORAGE_DISK`, обычно это `public`:

```dotenv
STORAGE_DISK=public
STORAGE_PUBLIC_URL=/media
```

Корни по умолчанию - `var/storage/public` и `var/storage/private`.
Каждый диск описывается ключами `driver`, `root`, `visibility` и необязательным `url`.

Сейчас фабрика поддерживает только `driver => local`, проверяет непустой корень и значения видимости `public` или `private`.

## Работа с файлами

Хранилище можно получить через конструктор сервиса:

```php
use App\Storage\Storage;

final class ReportFiles
{
    public function __construct(private Storage $storage) {}

    public function save(int $userId, string $csv): void
    {
        $this->storage->disk('private')->put('reports/'.$userId.'.csv', $csv);
    }

    public function read(int $userId): string
    {
        return $this->storage->disk('private')->get('reports/'.$userId.'.csv');
    }
}
```

Метод `disk(?string $name = null): Disk` возвращает указанный диск, а без аргумента - диск по умолчанию. Для основных операций доступны следующие методы:

| Метод                   | Назначение                    |
|-------------------------|-------------------------------|
| `put($path, $contents)` | Записать файл                 |
| `get($path)`            | Прочитать содержимое файла    |
| `exists($path)`         | Проверить существование файла |
| `delete($path)`         | Удалить файл                  |
| `url($path)`            | Сформировать ссылку на файл   |

Эти операции можно вызывать и непосредственно у `Storage`, если подходит диск по умолчанию. Например, `$storage->put(...)` не требует предварительного вызова `disk()`.

Методы `put()` и `delete()` не возвращают результат в виде `bool`: если операция завершается ошибкой, возникает исключение.

Для больших файлов предусмотрены `putStream()` и `readStream()`. 
Они позволяют работать с потоками без необходимости загружать всё содержимое в строку.
Открытый поток необходимо закрывать самостоятельно, например в блоке `finally`.

## Публичные и приватные файлы

Для файла на публичном диске можно сформировать ссылку через `url()`:

```php
use App\Storage\Storage;

function publish(Storage $storage, string $contents): string
{
    $disk = $storage->disk('public');
    $disk->put('exports/report.csv', $contents);

    return $disk->url('exports/report.csv');
}
```

Метод `url()` нормализует путь и кодирует его сегменты, но не проверяет, существует ли файл и доступен ли он по полученному адресу. 
Поэтому публичные ссылки будут работать только при корректно настроенной раздаче файлов веб-сервером.

Для приватного диска публичная ссылка обычно не предусмотрена. Если у него не настроен `url`, вызов `url()` приведёт к `LogicException`. 
Приватные файлы лучше отдавать через контроллер после проверки [прав доступа](/docs/{{version}}/authorization).

## Загрузка пользовательских файлов

Пример полноценной загрузки есть в `src/Modules/Account/Services/AvatarService.php`. 
При сохранении аватара приложение проверяет изображение через `ImageUploadValidator`, генерирует безопасное случайное имя файла, записывает его в хранилище и обновляет путь в данных пользователя.

Если обновление базы данных завершается ошибкой, новый файл удаляется. 
После успешного сохранения данных удаляется старый аватар. 
Такой подход помогает не оставлять лишние файлы при неудачных операциях.

**Важно:** транзакция базы данных не распространяется на файловое хранилище.
Откат транзакции Doctrine сам по себе не отменит запись или удаление файла.
Если операция изменяет и файлы, и данные в базе, порядок действий и обработку ошибок нужно продумать в сервисе.
