# Планировщик

Планировщик запускает консольные команды с заданной периодичностью.

За выполнение задач отвечает `app/Scheduler/Scheduler.php`, а команда `schedule:run` реализована в `app/Scheduler/ScheduleRunCommand.php`. 
Планировщик не работает сам по себе в фоне: его необходимо регулярно вызывать извне, например через cron.

## Настройка расписания

Задачи перечислены в `config/registrations/schedule.php`:

```php
return [
    ['command' => 'sessions:prune', 'every' => 3600],
    ['command' => 'users:remind', 'every' => 60],
];
```

`command` содержит имя зарегистрированной команды Symfony Console, а `every` задаёт интервал запуска в секундах.

Чтобы добавить свою задачу, сначала зарегистрируйте команду в `config/registrations/commands.php`, затем укажите её имя и интервал в расписании. 
Здесь используется именно имя команды, а не строка для выполнения в shell. 
Планировщик находит команду через `Application::find()` и запускает её с пустым `ArrayInput([])`, поэтому передавать аргументы через запись расписания нельзя.

Метод `status()` возвращает сведения о задачах, включая время последнего успешного запуска (`lastRun`). 
Само выполнение организовано методом `run()`, который вызывается консольной командой `schedule:run`. 
Обычно напрямую работать с этими методами не требуется.

## Запуск планировщика

Проверить задачи вручную можно из корня проекта:

```bash
./run console schedule:run -vv
```

Команда проверит расписание и покажет результат для каждой задачи: `completed`, `not_due`, `locked` или `failed`. 
Если хотя бы одна задача завершится с ошибкой, общий код завершения будет ненулевым.

Для регулярного запуска можно добавить запись в cron на хосте:

```cron
* * * * * cd /path/to/project && /usr/bin/docker compose exec -T app php bin/console schedule:run --no-interaction >> var/scheduler.log 2>&1
```

Такая запись вызывает планировщик каждую минуту, а уже он определяет, какие задачи пора выполнить.

Если задача только ставит сообщение в очередь, для его фактической обработки понадобится отдельный worker. 
Подробнее об этом - в разделе [Очереди](/docs/{{version}}/queues).

## Redis и защита от повторных запусков

Планировщик использует Redis сразу для двух целей: хранения времени последнего успешного выполнения через `App\Cache\Cache` и распределённых блокировок через Symfony Lock. 
Подключение задаётся в `config/definitions/scheduler.php` и зависит от [настроек кэша](/docs/{{version}}/cache).

Ключ состояния и имя блокировки формируются из имени команды. 
Поэтому две записи с одинаковой командой будут использовать общее состояние, а не два независимых расписания.

Блокировка действует до 3600 секунд и после выполнения освобождается. 
Автоматического продления в текущей реализации нет, поэтому для задач длительностью более часа потребуется изменить механизм блокировки.

Время последнего запуска обновляется только после успешного завершения команды с кодом `0` и сохраняется с TTL не менее суток.
Если команда завершилась с ошибкой или состояние не удалось записать, следующий вызов планировщика может запустить её повторно.

Очистка Redis также удалит историю успешных запусков. 
После этого задачи могут снова считаться готовыми к выполнению. 
Поэтому действия, которые нельзя без последствий повторять, стоит отдельно защищать от дублирования.
