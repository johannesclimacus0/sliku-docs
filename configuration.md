# Конфигурация

## Как устроена конфигурация

Конфигурация строится на трех уровнях:

- `.env` содержит переменные окружения.
- `config/settings/*.php` формируют настройки приложения на основе переменных окружения.
- `config/definitions/*.php` используют эти настройки при регистрации и создании зависимостей.

При запуске HTTP-приложения `App\Bootstrap\AppFactory::create()` загружает переменные из `.env` через `Dotenv::createImmutable($root)->safeLoad()`. 
Если переменная уже определена в окружении, ее значение не перезаписывается.

**При работе с Docker есть важный нюанс.** В `compose.yaml` используется `env_file`, который передает переменные окружения контейнеру при его создании. 
Поэтому после изменения `.env` недостаточно просто перезапустить приложение, контейнер нужно пересоздать:

```bash
docker compose up -d --force-recreate app
```

Если включен worker, после изменения окружения нужно пересоздать и его.

## Работа с конфигурацией

Файл `config/definitions/config.php` собирает настройки из `config/settings/`. Каждый файл становится отдельным разделом конфигурации: например, настройки из `config/settings/app.php` доступны через ключ `app`.

Для получения параметров используется класс `App\Config\Config`, который предоставляется компонентам приложения через контейнер зависимостей. 
Он предоставляет два метода:

- `get(string $key, mixed $default = null): mixed` - возвращает значение настройки или указанное значение по умолчанию.
- `has(string $key): bool` - проверяет существование ключа, даже если его значение равно `null`.

Например, получение названия приложения:

```php
use App\Config\Config;

final class ApplicationTitle
{
    public function __construct(
        private Config $config,
    ) {}

    public function value(): string
    {
        return $this->config->get('app.app_name', 'Sliku');
    }
}
```

Точечная нотация позволяет обращаться к вложенным параметрам. В данном примере `app.app_name` означает ключ `app_name` внутри раздела `app`.

Класс `Config` предназначен только для чтения настроек. Изменять значения или записывать их обратно в `.env` через него нельзя.

## Основные настройки

Все настройки приложения находятся в каталоге `config/settings/` и распределены по назначению.

| Файл              | Назначение                                               |
|-------------------|----------------------------------------------------------|
| `app.php`         | Название приложения, окружение, режим отладки и JWT-ключ |
| `database.php`    | Подключение к базе данных через Doctrine                 |
| `cache.php`       | Настройки кэширования                                    |
| `queue.php`       | Подключение и параметры очередей                         |
| `mail.php`        | Отправка электронной почты                               |
| `storage.php`     | Файловое хранилище                                       |
| `cors.php`        | Разрешенные источники для CORS                           |
| `rate_limits.php` | Ограничения частоты запросов                             |

Для добавления собственного параметра достаточно определить его в соответствующем файле настроек. После этого значение будет доступно через `Config`.

## Секреты и адреса

Во время первоначальной настройки команда `./run setup` генерирует значения для отсутствующих секретов:

- `JWT_KEY`
- `BROADCAST_TOKEN_KEY`
- `BROADCAST_API_KEY`
- `WEBHOOK_USER_SECRET`
- `WEBHOOK_NOTIFICATION_SECRET`

Уже заданные значения остаются без изменений.

При использовании Docker внутренние сервисы доступны по именам контейнеров:

```dotenv
DB_HOST=db
REDIS_URL=redis://redis:6379
```

Для отправки почты используется SMTP-сервер `mailpit:1025`.

При запуске приложения без Docker эти адреса необходимо заменить на доступные с локальной машины.
