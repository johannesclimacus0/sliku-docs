# Терминальная панель

TUI (Terminal User Interface) - интерактивная панель для управления проектом прямо из терминала. 

Панель запускается на компьютере разработчика, но получает данные приложения и выполняет часть команд через Docker Compose. 
Поэтому для работы нужны и локальный PHP, и подготовленное окружение проекта.

## Запуск

Из корня проекта выполните:

```bash
./run up -d
./run ui
```

Для панели нужны PHP 8.5 или новее на хосте, установленные Composer-зависимости, Docker Compose и интерактивный терминал. 
Symfony TUI и Process входят в dev-зависимости.

Проверить PHP и посмотреть справку можно отдельно:

```bash
php -v
./run ui --help
```

Запускайте TUI непосредственно в терминале.

Название в шапке берётся из `APP_NAME`. 
Панель читает `.env` при запуске, поэтому после изменения этой переменной её нужно открыть заново.

## Навигация

Слева расположено меню экранов, справа - содержимое выбранного раздела. Доступные действия показываются в нижней строке интерфейса.

| Клавиша            | Действие                                        |
|--------------------|-------------------------------------------------|
| `↑` / `↓`, `Enter` | Выбор и открытие пункта меню                    |
| `Tab`              | Переключение фокуса между меню и списком        |
| `Esc`              | Возврат из подробностей или отмена ввода        |
| `r`                | Обновление данных                               |
| `w` / `s`          | Прокрутка содержимого или перемещение по списку |
| `l`                | Открытие логов и переключение их источника      |
| `a`                | Переключение рисунка в боковой панели           |
| `q`                | Выход из TUI                                    |

`Ctrl+C` тоже закрывает панель, но при выполнении команды сначала прерывает текущую задачу. 
Во время ввода текста клавиши воспринимаются как символы: например, `q` в строке поиска не закроет интерфейс.

Данные обычно обновляются каждые пять секунд. 
Автоматическое обновление приостанавливается там, где оно мешало бы работе: при подтверждении действия, просмотре подробностей задания или остановке прокрутки логов.

## Основные экраны

| Экран        | Что показывает                                              |
|--------------|-------------------------------------------------------------|
| `overview`   | Проверки приложения, количество заданий и сводка расписания |
| `containers` | Сервисы Docker Compose и их состояние                       |
| `queue`      | Сообщения по транспортам и последние 20 заданий с ошибками  |
| `scheduler`  | Задачи расписания, интервалы и последний запуск в UTC       |
| `webhooks`   | Последние 10 доставок, их статусы, попытки и HTTP-коды      |
| `logs`       | Логи сервисов, поиск и просмотр отдельных записей           |
| `commands`   | Готовые действия, генераторы и запуск своих команд          |

Экран `scheduler` показывает состояние задач, но не запускает их автоматически. 
Для регулярного выполнения нужен внешний запуск `schedule:run`, а для обработки сообщений очереди - отдельный worker. 
Подробнее об этом рассказано в разделах [Планировщик](/docs/{{version}}/scheduling) и [Очереди](/docs/{{version}}/queues).

## Просмотр логов

Клавиша `l` открывает логи. Повторное нажатие переключает источники `app`, `worker` и `frontend`. Если Vite ещё не запускался, в логах фронтенда может быть пусто.

Для поиска нажмите `/`, введите текст и подтвердите `Enter`. Клавиша `f` переключает фильтр по уровню, а `p` приостанавливает обновление. Это удобно, когда новые сообщения быстро вытесняют нужную запись с экрана.

Чтобы открыть подробности, переведите фокус в список клавишей `Tab`, выберите запись и нажмите `Enter`. Длинный текст прокручивается клавишами `w` и `s`; `Esc` возвращает к списку. Пока открыты подробности, новые строки не заменяют текст перед глазами.

JSON-логи приложения отображаются в структурированном виде. Обычные строки вывода контейнеров тоже доступны для просмотра.

## Работа с заданиями очереди

На экране `queue` можно посмотреть последние задания, завершившиеся ошибкой, и выполнить действия над ними. 
Переключите фокус в список через `Tab`, выберите задание и откройте подробности клавишей `Enter`.

После этого доступны команды:

- `t` - повторить задание через `queue:retry`;
- `d` - удалить сообщение из транспорта `failed` через `queue:forget`.

Оба действия требуют подтверждения: `y` для выполнения, `n` или `Esc` для отмены.

Перед повтором стоит изучить исключение и устранить причину ошибки.
Повторная обработка может заново отправить письмо или вызвать внешний API, если сценарий не защищён от дублей.

## Команды и генераторы

Экран `commands` объединяет готовые операции: проверки PHP и фронтенда, работу с базой данных, инструменты проекта, генераторы классов и управление Vite. 
Действия выбираются через `Enter`; при необходимости сначала переключите фокус с меню клавишей `Tab`.

Генератор последовательно запрашивает имя класса и модуль. 
Например, имя `Reports/Monthly` и модуль `Account` создадут заготовку с вложенным пространством имён для выбранного типа. 
Используйте UpperCamelCase. Перед созданием файла панель покажет команду и запросит подтверждение.

Генерация создаёт только заготовку класса. 
Маршруты, команды, слушатели и обработчики при необходимости регистрируются отдельно. 
Подробнее - в разделе [Консоль](/docs/{{version}}/console).

В группе базы данных доступны просмотр состояния миграций, их применение, создание diff и добавление демонстрационных данных. 
Перед изменением базы панель запрашивает подтверждение. Интеграционные проверки backend используют отдельную базу `slim_test`, что отражено в названии соответствующего действия.

Вывод выполненной команды и её код завершения остаются на экране.
Длинный вывод прокручивается клавишами `w` и `s`, а `c` прерывает выполняемую задачу.
Прерывание процесса не откатывает изменения файлов или базы данных, которые уже успели произойти.

### Запуск своей команды

В группе `run a command` сначала выбирается окружение выполнения:

| Контекст                   | Где выполняется                    | Пример                 |
|----------------------------|------------------------------------|------------------------|
| `Host shell`               | На компьютере из корня проекта     | `git status --short`   |
| `PHP container shell`      | В запущенном контейнере `app`      | `php bin/console list` |
| `Frontend container shell` | Во временном контейнере `frontend` | `npm run type-check`   |

После ввода и нажатия `Enter` собственная команда запускается сразу, без дополнительного подтверждения `y/n`. 
Внутри PHP-контейнера используйте `php bin/console list`, а не `./run console list`: команда уже выполняется в нужном окружении.

Каждый запуск команды создаёт отдельный shell-процесс, поэтому `cd frontend`, выполненный одной командой, не изменит каталог следующей. 
Для последовательности действий используйте одну строку, например `cd frontend && npm run type-check` в контексте хоста.

Программы, которым нужен полноценный интерактивный TTY, лучше запускать в отдельном терминале. 
Историю команд выбранного контекста можно листать стрелками вверх и вниз, но она сохраняется только до закрытия панели.

### Управление Vite

Группа `frontend dev server` позволяет запускать Vite в фоне, останавливать его, проверять состояние и просматривать последние логи. 
После успешного запуска интерфейс доступен по адресу `http://localhost:5173`.

Vite продолжает работать после закрытия TUI. 
Для его остановки выберите `Stop Vite`. 
Закрытие панели также не останавливает Docker-контейнеры; команды управления окружением описаны в разделе [Установка](/docs/{{version}}/installation).

## Оформление панели

Клавиша `a` переключает рисунки из `resources/console/art/*.txt`. Они автоматически подстраиваются под доступное место и скрываются при ширине терминала менее 70 колонок.

Рисунок по умолчанию для каждого экрана определяется в `app/Console/UI/DashboardTheme.php`, а цвета - в `app/Console/UI/MikuColors.php`. 
Для изменения цветовой карты предусмотрен отдельный браузерный редактор.

Если интересна реализация TUI, начать можно с `bin/ui`: он проверяет окружение и запускает панель. 
`Dashboard.php` отвечает за экраны и клавиши, `Snapshot.php` собирает данные, `ComposeRunner.php` запускает процессы, а `LogPanel.php` и `CommandsPanel.php` реализуют соответствующие интерактивные разделы.

## Редактор артов

В стартере есть браузерный редактор для раскраски терминальных рисунков. Он открывает текстовые арты из `resources/console/art/`, позволяет назначать цвета отдельным символам и экспортировать PHP-код для TUI.

Редактор изменяет **цветовую карту**, а не исходные символы рисунка. Форму арта и содержимое `.txt` при необходимости редактируют отдельно.

### Запуск редактора

Из корня проекта выполните:

```bash
./run art:editor
```

Затем откройте `http://127.0.0.1:8090`. Команда запускает локальный PHP-сервер, который работает до остановки через `Ctrl+C`. Если порт занят, можно указать другой:

```bash
./run art:editor 8091
```

### Как хранятся цвета

За отображение отвечают три составляющие:

| Источник                      | Назначение                               |
|-------------------------------|------------------------------------------|
| `resources/console/art/*.txt` | Символы исходного рисунка                |
| `MikuColors::PALETTE`         | Соответствие коротких ключей HEX-цветам  |
| `MikuColors::GRIDS`           | Цветовой ключ для каждой позиции рисунка |

Константы `PALETTE` и `GRIDS` находятся в `app/Console/UI/MikuColors.php`. 
Например, ключ `h` может обозначать цвет волос, а `s` - кожи. Это просто имена оттенков, а не специальные команды.

Упрощённый пример:

```php
public const PALETTE = [
    'h' => '#53C4BE',
    's' => '#F9EEE8',
];

public const GRIDS = [
    'example' => [
        'hh.s',
        '.hss',
    ],
];
```

Каждая строка карты соответствует строке текстового рисунка, а каждый символ в ней определяет цвет отдельной позиции. 
Точка `.` обозначает стандартный цвет терминала. 

### Рабочее пространство

Слева находятся выбор рисунка, инструменты, отмена действий и настройки холста. 
В центре отображается увеличенная сетка, а справа - палитра, предварительный просмотр и экспорт.

В поле `art` можно выбрать любой читаемый `.txt` из каталога артов. 
Одна клетка редактора соответствует одному текстовому символу. 
Это относится и к Braille-символам, которые визуально состоят из нескольких точек: цвет назначается всему символу сразу.

Параметр `cell size` задаёт размер клетки от 8 до 30; его также можно менять через `Ctrl + Scroll` над холстом. 
Переключатель `grid` управляет сеткой, а `background` - фоном предварительного просмотра. Эти настройки не экспортируются в тему терминала.

### Инструменты рисования

| Инструмент | Клавиша | Действие                                             |
|------------|---------|------------------------------------------------------|
| `brush`    | `B`     | Раскрашивание выбранным цветом                       |
| `fill`     | `G`     | Заливка соседних клеток с одинаковым цветовым ключом |
| `pick`     | `I`     | Выбор цвета существующей клетки                      |
| `erase`    | `E`     | Возврат стандартного цвета терминала                 |

Предварительный просмотр меняется сразу. Взять цвет без смены инструмента можно правой кнопкой мыши или с удерживаемым `Alt`.

Заливка распространяется только на соседние клетки сверху, снизу, слева и справа. 
Диагональные соприкосновения не учитываются. 
Она сравнивает **ключи**, а не HEX-значения или форму символов: даже одинаковые цвета с разными ключами считаются разными областями.

По умолчанию включён `skip empty`, который защищает обычные пробелы и пустой Braille-символ `⠀` от окрашивания. 

### Экспорт в проект

Когда раскраска готова, нажмите `export` в правой части интерфейса. 
В открывшемся окне можно проверить сгенерированный PHP-текст, скопировать его или скачать файл `miku-colors.constants.txt`.

Дальше откройте `app/Console/UI/MikuColors.php` и замените объявления `PALETTE` и `GRIDS` экспортированными. 

Проверьте синтаксис и перезапустите панель:

```bash
php -l app/Console/UI/MikuColors.php
./run ui
```

Экспорт включает карты **всех** доступных артов, поэтому переносить нужно результат целиком.

### Добавление нового арта

Создайте текстовый UTF-8-файл, например `resources/console/art/my-miku.txt`, и поместите в него рисунок. 
Для масштабирования особенно подходят Braille-арты: терминальный рендерер умеет уменьшать точки таких символов. 
Произвольные Unicode-рисунки при уменьшении могут выглядеть иначе.

Перезагрузите редактор, выберите `my-miku` и настройте цвета. 
Для арта без карты используется стандартный цвет терминала. 
После экспорта добавьте результат в `MikuColors.php` и перезапустите TUI.

Новый рисунок появится в переборе по клавише `a`. 
Чтобы назначить его рисунком по умолчанию на конкретном экране, измените массив `ARTS` в `app/Console/UI/DashboardTheme.php`, указав имя без `.txt`.

### Если цвета не обновились

Если после экспорта видны старые цвета, проверьте, что изменения сохранены в нужном `MikuColors.php`, а TUI перезапущена. 
Переключите арт клавишей `a`: у разных экранов могут быть разные рисунки по умолчанию.

После изменения исходного `.txt` редактор может сообщить, что черновик больше не соответствует рисунку. 
Для проверки используются хеш содержимого и размеры карты. 
Если позиции символов изменились, старая раскраска может не подойти; редактор вернётся к карте из PHP. 
Переименованный файл с тем же содержимым он может сопоставить по хешу.

Внешний вид арта в терминале зависит от шрифта, фона и поддержки цветов. 
Параметр `background` в браузерном редакторе не меняет фон консоли.

### Где находится реализация

`tools/art-editor/router.php` отдаёт страницу редактора и `/data.json` с артами, палитрой и картами. 
`editor.js` управляет холстом, инструментами, историей, черновиками и экспортом, а `editor.css` отвечает за внешний вид.

В терминальной панели `app/Console/UI/Miku.php` читает и масштабирует рисунки, а `MikuColors.php` задаёт цвета. 
Остальное оформление TUI находится в `DashboardTheme.php`: экспорт цветовой карты не меняет цвета меню и рамок.
