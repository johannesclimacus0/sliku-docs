# Тестирование

Для проверок в стартере есть PHPUnit 12 и два набора: изолированные и интеграционные.
Изолированные проверки работают без внешних сервисов, а интеграционные выполняют сценарии с настоящей PostgreSQL-базой.

Конфигурация находится в `phpunit.xml`, вспомогательные классы - в `tests/Support`.

## Команды

```sh
./run test
./run test:isolated
./run test:integration
./run test:all
```

`./run test` запускает PHPUnit с параметрами конфигурации; набор по умолчанию - `Isolated`.
Команда `test:isolated` указывает его явно.
`test:integration` сначала выполняет `bin/test-database`, затем набор `Integration`; `test:all` готовит базу и запускает оба набора.
Все эти команды используют `docker compose exec -T app`, поэтому сначала запустите контейнер приложения и установите PHP-зависимости.

Можно передавать аргументы PHPUnit для выбора существующей проверки:

```sh
./run test --filter JwtTest
./run test:integration --filter AuthApiTest
./run test:prepare
```

Последняя команда только подготавливает интеграционную базу.
Прямой запуск `vendor/bin/phpunit` использует тот же `phpunit.xml`, но сам по себе не вызывает подготовку базы.

## Изолированное окружение

`Tests\Support\TestEnvironment` создает отдельный DI-контейнер и временный каталог.
Рабочие definitions и `.env` в это окружение не загружаются.
Кэш заменяется `ArrayAdapter`, очередь - `InMemoryTransport`, отправка писем - `RecordingMailTransport`, HTTP-клиент - `MockHttpClient`, файловое хранилище - локальными временными дисками.

Метод `work()` запускает настоящий Messenger worker над очередью в памяти, без задержек повторных попыток, до ее опустошения.
Это позволяет проверять обработчики и ошибки доставки без отдельного процесса и PostgreSQL.
`close()` очищает временные ресурсы.

Существующие проверки охватывают HTTP, JWT, маршрутизацию, CORS, кэш, хранилище, почту, очередь, scheduler и трансляцию.
Redis, SMTP и Centrifugo здесь заменены тестовыми реализациями.
Их реальную доступность нужно проверять отдельно.

## Интеграционная база

`Tests\Support\TestDatabase` использует фиксированное имя `slim_test`.
Подготовка подключается к базе `postgres`, создает тестовую базу при отсутствии и применяет миграции из `database/migration.php`.
Проверьте, что у пользователя PostgreSQL есть права на создание этой базы и применение миграций.
Для защиты перед очисткой проверяются драйвер `pdo_pgsql` и результат `SELECT current_database()`.

PHPUnit принудительно задает `APP_ENV=testing` и `DB_NAME=slim_test`.
Интеграционные настройки также отключают broadcast и обычные webhook endpoints, используют тестовый JWT-ключ.
Сами проверки могут подставлять собственные получатели для конкретного сценария.
Интеграционные сценарии охватывают Auth API, бизнес-ошибки, уведомления и их доставки.
